========================================================================
  TLB WORKFLOW TEST CASES
  pre-paging of the first 2 pages, and page-fault handling
  page = frame = 1024 B, VA 18 bits, TLB 32 entries
========================================================================

TC-01  Pre-paging loads exactly the first 2 pages
==========================================================================
  Input     : mm_prepage(pid 1)
  Setup     : fresh 32 MB memory, no process yet
  Expected  : return code            = 0
              PTE[0].present         = 1
              PTE[1].present         = 1
              PTE[2].present         = 0
              frames_held            = 2
              frames consumed        = 3
              disk reads             = 2
  Actual    : return code            = 0
              PTE[0].present         = 1
              PTE[1].present         = 1
              PTE[2].present         = 0
              frames_held            = 2
              frames consumed        = 3
              disk reads             = 2
  Result    : PASS
  Why       : The specification pre-pages the first 2 pages only. The third
              frame is the page table itself, which must be resident
              before any translation can happen -- hence
              MIN_FRAMES_PER_PROC = 3 = 2 pages + 1 page table.
              Two disk reads happened: pre-paging is real I/O.

TC-02  Pre-paging puts NOTHING in the TLB
==========================================================================
  Input     : inspect the TLB immediately after mm_prepage(pid 1)
  Setup     : pages 0 and 1 are resident in main memory
  Expected  : valid TLB entries      = 0
              probe(pid 1, vpn 0)    = -1
              probe(pid 1, vpn 1)    = -1
              16 B block fetches     = 0
  Actual    : valid TLB entries      = 0
              probe(pid 1, vpn 0)    = -1
              probe(pid 1, vpn 1)    = -1
              16 B block fetches     = 0
  Result    : PASS
  Why       : The specification says pre-paged "into main memory [not to
              cache]". The TLB caches TRANSLATIONS, and a translation
              only exists once something has been translated -- no
              reference has been made yet. So pre-paging populates the
              page table, not the TLB, and block_fetches = 0 confirms
              nothing reached L1/L2 either. The first instruction fetch
              is therefore a guaranteed TLB miss AND cache miss.

TC-03  First touch of a PRE-PAGED page: TLB miss, but no fault
==========================================================================
  Input     : read VA 0x00434  (page 1, offset 0x034)
  Setup     : page 1 pre-paged and present; TLB empty
  Expected  : status                 = OK (TLB miss, PTE present)
              TLB misses             = 1
              page-table walks       = 1
              page faults            = 0
              disk reads             = 0
              TLB entries now        = 1
  Actual    : status                 = OK (TLB miss, PTE present)
              TLB misses             = 1
              page-table walks       = 1
              page faults            = 0
              disk reads             = 0
              TLB entries now        = 1
  Result    : PASS
  Why       : This is the case pre-paging exists to create, and the reason
              the MMU returns THREE distinct success codes. A TLB miss
              whose walk finds the PTE already present costs ONE memory
              access and no disk I/O. Without pre-paging this same
              access would have been a page fault: a walk PLUS a disk
              read PLUS an instruction restart.

TC-04  Second touch of the same page: pure TLB hit
==========================================================================
  Input     : read VA 0x00438  (page 1 again, different offset)
  Setup     : the TLB now holds (pid 1, vpn 1)
  Expected  : status                 = OK (TLB hit)
              TLB hits               = 1
              page-table walks       = 0
              disk reads             = 0
  Actual    : status                 = OK (TLB hit)
              TLB hits               = 1
              page-table walks       = 0
              disk reads             = 0
  Result    : PASS
  Why       : Zero walks is the whole point of the TLB: the page table was
              not touched at all. Since page tables are never cached,
              every avoided walk is one avoided main-memory access.

TC-05  First touch of a NON-pre-paged page: full page fault
==========================================================================
  Input     : read VA 0x02534  (page 9, offset 0x134)
  Setup     : page 9 was never loaded: PTE[9].present = 0
  Expected  : status                 = OK (page fault serviced)
              TLB misses             = 1
              page-table walks       = 1
              page faults            = 1
              disk reads             = 1
              PTE[9].present         = 1
              frames_held grew by    = 1
              PA page offset         = 308
  Actual    : status                 = OK (page fault serviced)
              TLB misses             = 1
              page-table walks       = 1
              page faults            = 1
              disk reads             = 1
              PTE[9].present         = 1
              frames_held grew by    = 1
              PA page offset         = 308
  Result    : PASS
  Why       : The demand-paging path, end to end. Compare with TC-03: the
              TLB miss and the walk are identical -- what differs is
              that the PTE came back absent, so the OS had to allocate
              a frame and read the page from disk. The page offset
              0x134 is unchanged in the physical address, because
              translation only ever replaces the page number.

TC-06  The fault handler leaves the translation IN the TLB
==========================================================================
  Input     : read VA 0x02540 again (page 9, new offset)
  Setup     : the fault in TC-05 has just completed
  Expected  : status                 = OK (TLB hit)
              page-table walks       = 0
              page faults            = 0
              disk reads             = 0
  Actual    : status                 = OK (TLB hit)
              page-table walks       = 0
              page faults            = 0
              disk reads             = 0
  Result    : PASS
  Why       : A fault that did not fill the TLB would make the restarted
              instruction miss again, walk again, and -- because the
              PTE is now present -- silently cost a second memory
              access forever after. Step [7] of the flow inserts the
              mapping before the physical address is built.

TC-07  A FAILED access must not pollute the TLB
==========================================================================
  Input     : write to VA 0x0C810, on a page marked r--
  Setup     : PTE[50].prot = PROT_READ, page absent
  Expected  : status                 = FAULT: protection violation
              probe(pid 1, vpn 50)   = -1
              page faults            = 0
              disk reads             = 0
              PTE[50].present        = 0
  Actual    : status                 = FAULT: protection violation
              probe(pid 1, vpn 50)   = -1
              page faults            = 0
              disk reads             = 0
              PTE[50].present        = 0
  Result    : PASS
  Why       : Two things are proved at once. No TLB entry was created, so a
              later legal access is still forced through the page table.
              And no frame or disk read was spent: protection is checked
              immediately after the walk, BEFORE the fault path, so an
              access that can never succeed costs nothing but the walk.

TC-08  An out-of-range VA never reaches the TLB at all
==========================================================================
  Input     : read VA 0x40000  (= 2^18, one past the address space)
  Setup     : pid 1 is running normally
  Expected  : status                 = FAULT: address out of range
              TLB lookups performed  = 0
              valid TLB entries unchanged = 2
              pa_out left untouched  = 3735928559
  Actual    : status                 = FAULT: address out of range
              TLB lookups performed  = 0
              valid TLB entries unchanged = 2
              pa_out left untouched  = 3735928559
  Result    : PASS
  Why       : VA_VPN() masks to 8 bits, so 0x40000 would decode as PAGE 0 --
              and page 0 is resident, so the access would SUCCEED while
              reading completely the wrong page. The range check runs
              before the split, which is why zero TLB lookups happened.

TC-09  Every TLB miss costs exactly one page-table walk
==========================================================================
  Input     : 40 reads spread over 20 distinct pages of pid 2
  Setup     : pid 2 pre-paged, TLB shared with pid 1's entries
  Expected  : accesses               = 40
              TLB misses             = 20
              TLB hits               = 20
              page-table walks       = 20
              walks == misses        = 1
  Actual    : accesses               = 40
              TLB misses             = 20
              TLB hits               = 20
              page-table walks       = 20
              walks == misses        = 1
  Result    : PASS
  Why       : Each page is touched twice: the first touch misses and walks,
              the second hits. walks == misses is an invariant of the
              design -- the page table is consulted if and only if the
              TLB failed. Note pid 2's first 2 pages were pre-paged, so
              of the 20 misses only 18 became page faults.

TC-10  Pre-paged pages fault on their FIRST access only if evicted
==========================================================================
  Input     : pid 3 with upper_limit 4, then touch 12 distinct pages
  Setup     : cap forces the process to evict its own pages
  Expected  : peak resident frames   = 4
              final resident frames  = 4
              page faults            = 10
              free frames still ample = 1
  Actual    : peak resident frames   = 4
              final resident frames  = 4
              page faults            = 10
              free frames still ample = 1
  Result    : PASS
  Why       : Pre-paging is a head start, not a guarantee. Pages 0 and 1 came
              in free, so 12 pages touched cost only 10 faults. But the
              upper_limit caps the resident set at 4, so the pre-paged
              pages are evicted like any other -- and memory was never
              short (32000+ frames free), proving the CAP forced this,
              not scarcity.

TC-11  A fault that evicts a page kills that page's TLB entry
==========================================================================
  Input     : fault in a new page when memory is full and page 4 is coldest
  Setup     : memory filled; pid 1 holds pages 0-7; page 4 is in the TLB
  Expected  : page 4 is in the TLB before = 1
              status                 = OK (page fault serviced)
              PTE[4].present after   = 0
              probe(pid 1, vpn 4) after = -1
              page 60's new frame    = 43
  Actual    : page 4 is in the TLB before = 1
              status                 = OK (page fault serviced)
              PTE[4].present after   = 0
              probe(pid 1, vpn 4) after = -1
              page 60's new frame    = 43
  Result    : PASS
  Why       : This is the page-fault case that actually endangers the TLB.
              Frame reuse makes a cached translation a lie: a hit on
              page 4 would return a frame that now holds page 60. The
              fault handler notifies the MMU, which calls
              tlb_impl_invalidate_frame() BEFORE the frame is refilled.
              Note it is invalidated by FRAME, not by page, because a
              frame can be mapped from several page tables.

TC-12  Pre-paging both processes: TLB stays empty, memory does not
==========================================================================
  Input     : mm_prepage(pid 1); mm_prepage(pid 2)
  Setup     : fresh memory
  Expected  : frames consumed        = 6
              valid TLB entries      = 0
              pid 1 frames_held      = 2
              pid 2 frames_held      = 2
              demand page faults     = 0
  Actual    : frames consumed        = 6
              valid TLB entries      = 0
              pid 1 frames_held      = 2
              pid 2 frames_held      = 2
              demand page faults     = 0
  Result    : PASS
  Why       : 6 frames = 2 processes x (2 pre-paged pages + 1 page table).
              The TLB is still completely empty: pre-paging is a MEMORY
              event, not a translation event. And page_faults stays 0
              because pre-paged loads are planned, not demanded -- they
              cost disk reads but must not inflate the fault rate you
              report.

TC-13  Dead or unknown process is rejected before the TLB
==========================================================================
  Input     : read VA 0x00400 as pid 9 (never created)
  Setup     : only pid 1 and pid 2 exist; pid 1 is running
  Expected  : status                 = FAULT: process not runnable
              TLB lookups performed  = 0
              page-table walks       = 0
  Actual    : status                 = FAULT: process not runnable
              TLB lookups performed  = 0
              page-table walks       = 0
  Result    : PASS
  Why       : Step [2] runs before step [3]. Without it the TLB would be
              probed with a PID that owns no page table, and a stale
              entry from a recycled PID could produce a hit for a
              process that does not exist.

TC-14  Execute permission is enforced separately from read
==========================================================================
  Input     : X (instruction fetch) on page 30 marked rw- , then on page 31 marked r-x
  Setup     : pid 1 running; both pages absent
  Expected  : X on rw- page (absent) = FAULT: protection violation
              X on r-x page (absent) = OK (page fault serviced)
              W on r-x page, TLB cached = OK (TLB hit)
              W on r-x page, after invalidate = FAULT: protection violation
              probe(pid 1, vpn 30)   = -1
  Actual    : X on rw- page (absent) = FAULT: protection violation
              X on r-x page (absent) = OK (page fault serviced)
              W on r-x page, TLB cached = OK (TLB hit)
              W on r-x page, after invalidate = FAULT: protection violation
              probe(pid 1, vpn 30)   = -1
  Result    : PASS
  Why       : Three access types, three independent permission bits: page 30
              is rw- so a fetch is refused, page 31 is r-x so a fetch
              succeeds but a write is refused. The third line is the
              honest part -- my FIRST version of this case expected the
              write to fault, and the harness caught the wrong
              EXPECTATION, not a code bug: page 31 was cached by the
              successful fetch, and a TLB hit carries no protection
              bits. Line four forces the walk and the check fires.
              Also note page 30 left no TLB entry: a refused access
              never caches a translation.

TC-15  The aging timer fires automatically every N accesses
==========================================================================
  Input     : tick_interval = 5, then 20 accesses that never touch page 5
  Setup     : page 5 faulted in (aging = 0x80, referenced = 1)
  Expected  : aging before ticks     = 128
              ticks that should fire (20/5) = 4
              aging after 4 ticks    = 24
              referenced bit cleared = 0
  Actual    : aging before ticks     = 128
              ticks that should fire (20/5) = 4
              aging after 4 ticks    = 24
              referenced bit cleared = 0
  Result    : PASS
  Why       : Hand-computed: 0x80 -> (0x80>>1)|0x80 = 0xC0 on the first tick
              (its reference bit was still set from the fault), then
              0x60, 0x30, 0x18 as it goes unreferenced. An unused page
              decays exponentially, which is exactly what stops plain
              LFU from keeping a once-hot page resident forever.

TC-16  A page fault into a FULL TLB evicts the LRU entry
==========================================================================
  Input     : touch 32 distinct pages to fill the TLB, then fault a 33rd
  Setup     : memory is plentiful; only the TLB is under pressure
  Expected  : valid TLB entries      = 32
              TLB evictions so far   = 0
              status                 = OK (page fault serviced)
              valid TLB entries after = 32
              TLB evictions          = 1
              page 0 survived (was touched) = 1
              page 1 evicted (was LRU) = -1
  Actual    : valid TLB entries      = 32
              TLB evictions so far   = 0
              status                 = OK (page fault serviced)
              valid TLB entries after = 32
              TLB evictions          = 1
              page 0 survived (was touched) = 1
              page 1 evicted (was LRU) = -1
  Result    : PASS
  Why       : Two independent resources can be full at once. Here memory has
              32000+ free frames, so the fault is cheap, but the TLB is
              at capacity and must drop something. Page 0 was refreshed
              just before, so LRU protects it and kills page 1 -- under
              FIFO page 0 would have died instead.

TC-17  upper_limit self-eviction ALSO invalidates the TLB
==========================================================================
  Input     : pid 1 capped at 4 frames touches pages 0..5
  Setup     : memory is plentiful -- only the per-process cap forces eviction
  Expected  : resident frames        = 4
              pages evicted by the cap = 2
              evicted pages still in TLB = 0
              free frames still ample = 1
  Actual    : resident frames        = 4
              pages evicted by the cap = 2
              evicted pages still in TLB = 0
              free frames still ample = 1
  Result    : PASS
  Why       : The upper_limit branch is a SECOND eviction path, separate from
              the global victim search, and it is easy to forget that it
              needs the same invalidation. It goes through the same
              evict_frame() helper, so the notification fires and the
              TLB is cleaned -- this case proves that, rather than
              assuming it.

TC-18  No evictable frame anywhere: MMU_FAULT_NO_FRAME
==========================================================================
  Input     : fault a new page when every frame is pinned
  Setup     : all free frames taken as page-table frames; pid 1 sits at its lower_limit
  Expected  : free frames            = 0
              pid 1 frames_held      = 2
              pid 1 lower_limit      = 3
              mm_select_victim       = -1
              status                 = FAULT: no evictable frame
              pa_out untouched       = 286331153
              disk reads             = 0
              probe(pid 1, vpn 40)   = -1
  Actual    : free frames            = 0
              pid 1 frames_held      = 2
              pid 1 lower_limit      = 3
              mm_select_victim       = -1
              status                 = FAULT: no evictable frame
              pa_out untouched       = 286331153
              disk reads             = 0
              probe(pid 1, vpn 40)   = -1
  Result    : PASS
  Why       : The out-of-memory leaf of the flowchart, and the one path I had
              previously left untested. Every allocated frame is a page
              table (never evictable) and pid 1 is at its floor (2 held,
              limit 3), so nothing may be taken. The MMU reports the
              failure instead of violating a limit, leaves pa_out alone,
              spends no disk I/O, and creates no TLB entry.

TC-19  A spurious fault on an already-present page is a no-op
==========================================================================
  Input     : call mm_handle_fault(pid 1, page 1) -- page 1 is already resident
  Setup     : page 1 was pre-paged
  Expected  : return code            = 0
              page faults added      = 0
              disk reads added       = 0
              frames_held added      = 0
              frame unchanged        = 103
  Actual    : return code            = 0
              page faults added      = 0
              disk reads added       = 0
              frames_held added      = 0
              frame unchanged        = 103
  Result    : PASS
  Why       : Real systems reach this after a TLB shootdown or two faults
              racing on the same page. Treating it as a fresh fault
              would allocate a SECOND frame for a page that already has
              one -- leaking the first frame permanently and double
              counting the fault.

TC-20  Pre-paging fails cleanly when memory cannot supply 3 frames
==========================================================================
  Input     : mm_prepage(pid 1) with zero free frames
  Setup     : every frame allocated before the process is created
  Expected  : free frames            = 0
              return code            = -1
              page table left NULL   = 1
              frames_held            = 0
  Actual    : free frames            = 0
              return code            = -1
              page table left NULL   = 1
              frames_held            = 0
  Result    : PASS
  Why       : A process that cannot get its 3 minimum frames must not start
              half-initialised. Returning -1 with pt == NULL means the
              later translate() call hits step [2] and reports
              NO_PROCESS rather than dereferencing a null page table.

TC-21  A dirty victim is written back, and its TLB entry dies
==========================================================================
  Input     : write page 3, fill memory, then fault page 80 so page 3 is the victim
  Setup     : pid 1 holds pages 0-7; page 3 has been written to
  Expected  : PTE[3].dirty           = 1
              page 3 cached in TLB   = 1
              disk write-backs       = 1
              PTE[3].present after   = 0
              probe(pid 1, vpn 3) after = -1
              page 80 took frame     = 108
  Actual    : PTE[3].dirty           = 1
              page 3 cached in TLB   = 1
              disk write-backs       = 1
              PTE[3].present after   = 0
              probe(pid 1, vpn 3) after = -1
              page 80 took frame     = 108
  Result    : PASS
  Why       : Both consequences of one eviction. The page differs from disk,
              so it is written back -- and because BOTH caches are
              write-through, main memory already held the newest bytes,
              so no cache flush was needed first. Meanwhile the TLB
              entry must die or it would point at page 80's frame.

TC-22  Process exit clears its TLB entries and frees its frames
==========================================================================
  Input     : pid 2 touches 6 pages, then terminates
  Setup     : pid 1 and pid 2 both running, sharing the 32-entry TLB
  Expected  : pid 2 TLB entries before = 6
              pid 2 TLB entries after = 0
              frames returned (6 pages + 1 page table) = 7
              pid 1 still cached     = 1
              pid 1 frames untouched = 4
  Actual    : pid 2 TLB entries before = 6
              pid 2 TLB entries after = 0
              frames returned (6 pages + 1 page table) = 7
              pid 1 still cached     = 1
              pid 1 frames untouched = 4
  Result    : PASS
  Why       : The bulk invalidation the specification names explicitly. The
              +1 frame is the page table, which replacement can never
              touch -- exit is the ONLY path that frees it, so missing
              this leaks a frame per terminated process. And the sweep
              is PID-scoped: pid 1 keeps every entry and every frame.

TC-23  KNOWN LIMITATION: revoking permission is invisible to a TLB hit
==========================================================================
  Input     : read page 20 (caches it), revoke write permission, then write to it
  Setup     : pid 1 running; page 20 will be resident and TLB-cached
  Expected  : status of the illegal write = OK (TLB hit)
              PTE says writable      = 0
              after invalidating the entry = FAULT: protection violation
  Actual    : status of the illegal write = OK (TLB hit)
              PTE says writable      = 0
              after invalidating the entry = FAULT: protection violation
  Result    : PASS
  Why       : This test asserts the BUG, deliberately, so it is documented and
              cannot regress silently. TLBImplEntry carries no prot bits,
              and re-reading the PTE on every hit would cost a memory
              access per reference and defeat the TLB entirely. So the
              write is permitted until the entry is invalidated -- which
              the driver's PROT directive does for exactly this reason.
              Real fix: add 'prot : 3' to TLBImplEntry, which needs
              TLB.h -- a file this work does not modify.
