TC-01  Pre-paging loads exactly the first 2 pages
==========================================================================
  Input     : mm_prepage(pid 1)
  Setup     : fresh 32 MB memory, no process yet
  Expected  : return code            = 0
              PTE[0].present         = 1
              PTE[1].present         = 1
              PTE[2].present         = 0
              frames_held            = 2
              frames consumed        = 3
              disk reads             = 2
  Actual    : return code            = 0
              PTE[0].present         = 1
              PTE[1].present         = 1
              PTE[2].present         = 0
              frames_held            = 2
              frames consumed        = 3
              disk reads             = 2
  Result    : PASS
  Why       : The specification pre-pages the first 2 pages only. The third
              frame is the page table itself, which must be resident
              before any translation can happen -- hence
              MIN_FRAMES_PER_PROC = 3 = 2 pages + 1 page table.
              Two disk reads happened: pre-paging is real I/O.

TC-02  Pre-paging puts NOTHING in the TLB
==========================================================================
  Input     : inspect the TLB immediately after mm_prepage(pid 1)
  Setup     : pages 0 and 1 are resident in main memory
  Expected  : valid TLB entries      = 0
              probe(pid 1, vpn 0)    = -1
              probe(pid 1, vpn 1)    = -1
              16 B block fetches     = 0
  Actual    : valid TLB entries      = 0
              probe(pid 1, vpn 0)    = -1
              probe(pid 1, vpn 1)    = -1
              16 B block fetches     = 0
  Result    : PASS
  Why       : The specification says pre-paged "into main memory [not to
              cache]". The TLB caches TRANSLATIONS, and a translation
              only exists once something has been translated -- no
              reference has been made yet. So pre-paging populates the
              page table, not the TLB, and block_fetches = 0 confirms
              nothing reached L1/L2 either. The first instruction fetch
              is therefore a guaranteed TLB miss AND cache miss.

TC-03  First touch of a PRE-PAGED page: TLB miss, but no fault
==========================================================================
  Input     : read VA 0x00434  (page 1, offset 0x034)
  Setup     : page 1 pre-paged and present; TLB empty
  Expected  : status                 = OK (TLB miss, PTE present)
              TLB misses             = 1
              page-table walks       = 1
              page faults            = 0
              disk reads             = 0
              TLB entries now        = 1
  Actual    : status                 = OK (TLB miss, PTE present)
              TLB misses             = 1
              page-table walks       = 1
              page faults            = 0
              disk reads             = 0
              TLB entries now        = 1
  Result    : PASS
  Why       : This is the case pre-paging exists to create, and the reason
              the MMU returns THREE distinct success codes. A TLB miss
              whose walk finds the PTE already present costs ONE memory
              access and no disk I/O. Without pre-paging this same
              access would have been a page fault: a walk PLUS a disk
              read PLUS an instruction restart.

TC-07  A FAILED access must not pollute the TLB

  Input     : write to VA 0x0C810, on a page marked r--

  Expected  : status                 = FAULT: protection violation

              access that can never succeed costs nothing but the walk.

TC-09  Every TLB miss costs exactly one page-table walk
==========================================================================

  Setup     : pid 2 pre-paged, TLB shared with pid 1's entries
  Expected  : accesses               = 40
              TLB misses             = 20

  Actual    : accesses               = 40

              of the 20 misses only 18 became page faults.
